# 架构与边界（ARCHITECTURE）

> 本文只描述**结构**与**边界**，不含任何真实会话数据、玩家信息或参数拟合结果。

## 1. 分层

```
cash_game_ui/            ← 展示层：一键分析、结果渲染、本地日志
  runner.py                   点击链路（Capture → Vision → Decision）与旁路功能
  preview_gui.py              GUI（Tk）

poker_decision_ai/
  core/orchestration/    ← 编排层：任务、重试、预算、上下文
  core/providers/        ← Provider 层：LLM / 视觉 / 求解器 / 规则（可插拔）
  core/repositories/     ← 仓储层：JSONL 持久化 + 内存索引
  agents/                ← 领域 Agent：状态、范围、求解、下注尺度、剥削…
  domain/poker/          ← 纯领域模型：牌、范围、组合、权益、条件模型
  vision2/               ← 视觉层：截图 → 规范化观测（含像素级识别器）
  action_semantics.py    ← 动作语义与**安全不变量**（见 §3）
  facing_evidence.py     ← "是否面对下注"的证据推导
```

## 2. 数据流（一次点击）

```
RGBA 帧
  ├─ 几何归一化：非参考尺寸（1876×1400）⇒ 缩放（±8%）或拒识（诚实 UNKNOWN）
  ├─ 视觉：多识别器并行/串行 → 规范化观测 {seats, board, pot, to_call, …}
  │    每个字段都带来源与置信；读不到 ⇒ NULL/UNKNOWN（绝不猜）
  ├─ 观测缓存：以帧哈希为键（同帧复用 ✓；决策**不**缓存 ✗）
  ├─ 决策：编排 → Provider（求解器/启发式/LLM）→ final_decision
  │    每一步保留 basis / confidence / evidence
  └─ 安全不变量校验（§3）→ 结果与理由
```

## 3. 安全不变量（最重要的设计）

**弃牌/跟注只在"确实面对下注"被确立时才允许输出** ✓。理由：如果能免费过牌，
弃牌与跟注都是**被支配**的（跟注若非法则更糟）。

判定顺序：

1. **显式合法动作集**（若视觉/桥给出）⇒ 最高优先；
2. **`to_call > 0` 且 < 底池** ⇒ 面对下注成立 ——
   注意 **`to_call ≥ 底池` 在算术上不可能**（底池已含那笔下注），一律判为不可信 ✗；
3. **逐座位前置下注**（`v3f_bets`）⇒ 仅作**旁证**：单凭"对手桌前筹码更多"不足以断定
   "现在必须跟"（可能是底池筹码展示或已跟过的旧注），因此**降级为 UNKNOWN** ✓；
4. 都未成立 ⇒ 已知能过牌则**改写为过牌** ✓；否则**撤回动作**（诚实"信息不足"）✓。

> 这条不变量是踩过真实坑才加的：曾出现"能过牌却建议弃牌/跟注"的被支配建议。

## 4. 视觉识别的几何契约

* 参考几何：**1876×1400**；其它尺寸按 ≤8% 缩放归一化，超出则**拒识**（不猜）；
* 牌面槽位：`X0=590, W=140`（1876 渲染），并可**按白卡斑块实测校正**；
* 人头牌（J/Q/K）卡面中心是**图案**而非花色 ⇒ 花色需由"角标高分 + 红黑颜色一致"双证据支撑；
* 牌面倾斜时，角标字形需要**小角度扫描**（达门即停 ✓）。

## 5. 你需要自备的资产（清单）

| 资产 | 目录（约定）| 说明 |
|---|---|---|
| 卡面 rank/suit 模板 | `data/vision2/coinpoker_assets_*` | 由你自己的截图标注；**不得包含他人昵称** |
| 数字/筹码字形模板 | 同上 | 用于底池/筹码/跟注额 |
| 求解器可执行文件 | `tools/bin/` | 第三方；自行获取与配置 |

缺少资产时，相关识别结果为 `UNKNOWN`，程序**降级并明确标注**，不会编造。

## 6. 门禁与测试的设计意图

* **不存在"报告好看"的捷径**：所有汇总数字都由脚本从原始产物计算；
* **口径一致性检查**：审计脚本会把"文档里写的数字"与"实测产物"对比，不一致即失败；
* **夹具驱动**：识别类改动必须用真实帧夹具回归（夹具**不随仓库分发** ⇒ 自动 skip）；
* **可回退**：性能/行为优化都挂在环境变量上，出问题可立即关闭。

## 7. 反模式（本项目刻意避免）

* ✗ 拿"预解本机库命中率"当能力证明；
* ✗ 拿无法对齐范围/抽象的第三方数据集当"能力评价"；
* ✗ 用"循环论证"的 EV 数字（用自己求解的结果给自己的决策打分）当证据；
* ✗ 在证据不足时"补全"字段（宁可 `UNKNOWN`）。
